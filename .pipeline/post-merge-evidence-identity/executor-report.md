## 本轮：证据身份改为阶段分工

上一版契约要求「放宽 `branch`/`worktree` 的相等性」，本版推翻它，改为**阶段分工**：`finalized`（post-merge）阶段的证据身份**只有任务单 id 与 `sheet_revision`**，提交引用一律降为记录事实；`active`（pre-merge）阶段的完整提交绑定**逐字不变**。理由在契约里是机械的：合并本身必然在当前 HEAD 上引入产品路径提交，所以 post-merge 阶段 `head == HEAD`、「仅被证据提交推进」、`observed_at_commit` 的路径相交判据都不可能成立。

严格按契约「设计与行为契约」的表实现，逐行对照：

| 契约表中的判据 | active | finalized | 实现位置 |
|---|---|---|---|
| 证据文件齐全、角色正确、验收 ID 一致、逐条 PASS、`evidence_ref` 可解析 | 保留 | 保留 | `evidence_verify` 未改动部分（`core.py:499` 起） |
| 报告写明所评判的 `sheet_revision` | 保留 | 升为身份 | `core.py:603-610`（finalized 分支：缺失/非整数 → `sheet_revision must be a positive integer`；不等于当前修订 → 复用 `was produced against task sheet revision N but the current revision is M`） |
| `task_id` 与受验任务一致 | 保留 | 升为身份 | `core.py:521-523`（既有 `task identity mismatch`）+ `core.py:525`（finalized 新增：`evidence directory does not match the verified task id`） |
| 主工作树复验命令（`cwd` = 主工作树根、退出码 0） | — | 保留 | 既有 `_post_merge_reverified_in_main_worktree`（`core.py`）/ `reconcile.py:190` |
| `head` 等于 HEAD 或仅被证据提交推进 | 保留 | 不做判定 | `core.py:583-592` 仅在 `commit_bound` 时执行 |
| `branch`、`worktree` 等于当前身份 | 保留 | 不做判定 | `core.py:593-604` 仅在 `commit_bound` 时执行 |

| 四个字段存在且格式合法 | 必需 | 必需（记录事实） | 既有 `head` 40 位/非空、`worktree` 非空检查对两相都生效；finalized 追加 `core.py:612-619`（`branch`、`observed_at_commit` 必须是非空字符串） |

- 阶段取值：沿用既有 `--phase {active, finalized}` 与 `gate pre-merge|post-merge`，**没有改变任何既有取值的语义**——`finalized` 仍然是"已合并/已终审"的同一阶段（它还会照旧校验 `finalization.json` marker），只是该阶段的身份判据按新版契约执行；`active` 是默认值，判定与错误文本逐字未变。`evidence_verify` 新增第 4 个位置参数 `phase="active"`，取值不在 `EVIDENCE_PHASES`（`core.py:51`）时 `raise ValueError`（fail-closed，与 `_canonical_evidence_dir` 的行事方式一致）。
- `gate_check`（`core.py:2009`）把 `phase == "post-merge"` 映射为 `finalized`、其余映射为 `active`；`planning._finalize_evidence_unlocked`、`task_lifecycle` 的 merged 过渡都经由 `gate_check`，因此一并生效。
